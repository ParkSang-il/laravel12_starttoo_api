# 스트릿펫 v2 친구 상세·상태 API 변경

2026-11-04. 서버 소스 구현과 격리 테스트 완료. 운영 배포·실제 MySQL 검증은 미실행.
기준 경로는 `/api/v1/projects/streetcat/groups/{group}/places/{place}/animals`.

## 변경 범위

- GET `/{animal}`: 친구 단독 상세. 현재 프로젝트·가입·장소 열람 권한과 해당 장소 연결을 확인한다. 다른 장소 ID·좌표·로컬 원본 식별자는 반환하지 않는다.
- POST, import, PATCH 및 목록/상세 응답에 TNR 단계·날짜와 생애 상태 변경일을 지원한다.
- PATCH는 기존대로 `version` 필수이며 변경할 항목만 보낼 수 있다. 그룹 잠금, 감사 이벤트, 403/404/409 처리를 유지한다. 감사 로그에는 날짜·메모 값 대신 필드명만 남긴다.
- 그룹 생성의 동 코드·동 이름 필수 조건을 제거했다. 기존 지역 기반 discover 경로와 구버전 요청은 호환성을 위해 유지한다. 근처 검색의 좌표 반올림·권한 정책은 기존대로다.
- 연결 후보 조회의 NOT EXISTS 서브쿼리를 LEFT JOIN으로 정리했다.

## 필드 계약

| 필드 | 형식 | 규칙 |
|---|---|---|
| tnr_stage | needed / trapScheduled / surgery / released / done | TNR 필요 / 포획 예정 / 수술 / 방사 / 완료 |
| tnr_dates | 단계명 → YYYY-MM-DD 또는 null 객체 | 필요 단계를 제외한 네 단계만 허용. 2000-01-01부터 오늘+365일까지. 선택 단계 이후의 입력 날짜는 422 |
| neutered | boolean | 수술·방사·완료이면 true. 명시한 tnr_stage와 불일치하면 422 |
| life_status | active / missing / rescued / moved / passedAway | 활동 중 / 실종 의심 / 구조입양 / 이사 / 별이 됨 |
| life_status_at | YYYY-MM-DD 또는 null | 2000-01-01부터 오늘까지. 활동 중이면 null. 활동 중에 날짜를 지정하면 422 |

`tnr_dates`는 응답에서 빈 경우에도 `{}` 객체다. 명시적으로 필요 이외 단계로 변경하면 선택 단계의 날짜가 필요하다. 기존 저장 날짜가 있으면 재사용할 수 있다. 날짜만 수정할 때도 tnr_stage를 함께 보낸다. 주어진 날짜 키는 기존 날짜와 병합하고 null은 해당 날짜를 지운다. 선택한 단계 이후의 기존 날짜는 제거한다. 예: 완료 → 수술로 돌아가면 방사·완료 날짜를 제거한다. TNR 필요로 돌아가면 전체 날짜를 지운다.

활동 중으로 복귀하면 상태 날짜를 지운다. 다른 상태로 바꾸면서 날짜를 생략하면 서버의 오늘 날짜를 기록한다. 상태가 그대로면 기존 날짜를 보존하며, 명시적 null은 알 수 없는 날짜로 저장한다. 날짜는 프로젝트가 사용하는 서버 시간대의 달력 날짜이며 시각·UTC 변환 값이 아니다.

예시:

```json
{"version":3,"tnr_stage":"surgery","tnr_dates":{"surgery":"2026-11-04"}}
```

```json
{"version":4,"life_status":"rescued","life_status_at":"2026-11-04"}
```

단독 상세의 `data`는 기존 친구 기본정보와 `tnr_stage`, `tnr_dates`, `life_status_at`, `version`, `can_manage`를 포함한다. 목록은 기존 `data.animals` 및 페이지 구조를 유지한다. 요청 예시는 `animals.http`에 추가했다.

## 구버전 앱·기존 데이터

- 기존 neutered=true 친구는 마이그레이션에서 완료로, false는 TNR 필요로 유지한다. 알 수 없는 과거 날짜는 만들지 않는다.
- 단계 없이 neutered만 바꾸는 구버전 요청은 필요/완료로 처리한다. 값이 이전과 같으면 저장 중인 세부 단계를 보존한다. 예: 수술 단계에서 전체 수정 폼이 neutered=true를 다시 보내도 완료로 바뀌지 않는다.
- region_code/region_label은 신규 그룹에서 생략·null이 가능하다. 기존 유효한 값과 인덱스는 유지하며 임의 지역 코드로 채우지 않는다.
- 프로젝트 DB는 분리돼 있다. 개인 SQLite 친구·사진·위치·건강 기록을 서버에 자동 저장하지 않는다.

## 인증 및 테스트 정리

요청 경계에서 JWT 객체의 이전 토큰도 초기화한다. 기존 guard 초기화만으로는 반복 요청에서 다른 토큰이 남을 수 있어 프로젝트 간 토큰 격리 테스트가 실패했으며, 수정 후 통과했다. 세션 만료 검사는 유지한다. 그룹 테스트의 수동 발급 JWT에는 실제 정책에 맞는 세션을 준비하고, 미들웨어 순서 테스트는 HTTP 커널을 먼저 초기화한다.

테스트 작성 및 로컬에서 동작 확인: 기존 composer.lock 그대로 설치한 PHP 8.3 컨테이너의 임시 디렉터리에서 `php artisan test` 전체 59개(708 assertions) 통과. SQLite 메모리 DB만 사용했다. TNR 5단계, 날짜 오류, 단계 복귀, 구버전 호환, 상태 5종, 부분 수정, 충돌, 열람·관리 권한, 장소 미연결, 프로젝트 격리, 마이그레이션 데이터 보존을 검증했다. MySQL 동시 요청·실기기·실서비스 배포 검증은 미실행이다.

## 배포 순서

1. DB 백업 후 기존 프로젝트별 배포 절차로 새 migration 000009·000010을 적용한다. 운영 DB에 fresh/refresh는 실행하지 않는다.
2. `php artisan project:migrate streetcat --pretend`로 SQL을 검토하고 `php artisan project:migrate streetcat --force`를 실행한다. 이번 작업에서는 운영 DB 명령을 실행하지 않았다.
3. `php artisan optimize:clear` 후 실제 계정으로 단독 상세·TNR PATCH·상태 PATCH와 권한 회수·409 응답을 확인한다.
4. Flutter에 새 필드 파싱, 단계별 날짜 선택·PATCH 및 조회 반영을 연결한다. 현재 앱의 중간 단계 저장 준비 중 표시는 서버 배포만으로 바뀌지 않는다.

000010 rollback은 지역 없는 그룹이 있으면 중단한다. 지역을 임의 생성하거나 그룹을 삭제하지 않는다. 000009 rollback은 새 단계·날짜 컬럼을 제거하므로 새 정보가 필요하면 rollback 대신 이전 코드와 호환되는 전진 배포를 사용한다.

## 별도 범위

공동 건강 기록, 사진 업로드, 그룹 아바타·활동 집계, 후원 목록·결제는 이번 API 작업의 완료 범위가 아니다. 별도 데이터·권한·보관 계약이 필요하며 화면의 준비 중 표시를 유지한다.


## 공동돌봄 프로필 통일 후속 변경

홈·그룹·활동·멤버가 같은 계정 ID·프로필 URL을 사용하도록 응답을 확장했다. 신규 migration 000011과 읽기 전용 사진 필드, 권한·해상도 정책은 [공동돌봄 프로필 계약](GROUP_PROFILES.md)을 따른다. 전체 서버 테스트 62개(768 assertions) 통과. 운영 DB 적용·배포·사진 등록 기능은 미실행이다.

## 2026-11-04 프로필 사진 업로드/삭제

`POST me/avatar`(multipart `photo`) 및 `DELETE me/avatar`를 인증 경로에 추가했다. 프로젝트 migration 000012로 `project_accounts`에 관리용 객체 경로를 추가한다. 저장 위치는 `profile/YYYY/MM/DD/{projectCode}/{accountId}/`이며 버킷은 `.env`의 `AWS_BUCKET=streetcat`이다. DB에는 비공개 파일 경로, 응답에는 1시간 유효한 URL을 제공한다. 기존 홈·그룹·활동·멤버 프로필 응답의 필드명과 접근 권한은 유지한다. 등록·삭제 앱 화면, 실패 보존·프로젝트 격리·그룹 응답 검증 및 배포 절차는 `docs/GROUP_PROFILES.md`를 따른다. 67개 격리 서버 테스트 통과. 운영 배포·DB 적용은 미실행.

## 친구 상태·TNR 전용 저장 및 고정 닉네임 번호

### 상태·TNR

`PATCH /api/v1/projects/{projectCode}/groups/{group}/places/{place}/animals/{animal}/status`를 추가했다. 기존 친구 전체 수정 PATCH도 유지한다. 상태 전용 API는 `version`과 하나 이상의 `tnr_stage`/`life_status`를 받으며 다른 일반 정보는 받지 않는다.

```json
{"version":3,"tnr_stage":"surgery","tnr_dates":{"surgery":"2026-11-04"}}
```

```json
{"version":4,"life_status":"missing","life_status_at":"2026-11-04"}
```

TNR 필요로 돌아가면 이후 단계 날짜를 지운다. 그 외 단계는 선택한 단계 날짜가 필요하다. 중성화 여부는 수술/방사/완료이면 true로 계산한다. 상태는 활동 중/실종 의심/구조입양/이사/별이 됨이며 활동 중 외에는 변경 날짜를 필수로 받는다. 활동 중으로 되돌리면 날짜를 초기화한다. 단계 날짜는 2000년부터 1년 후까지, 상태 날짜는 오늘까지 허용한다. 서버가 기존 단계 날짜를 보존하고 뒤로 이동하면 이후 날짜를 정리한다.

운영자 권한·친구와 장소의 연결·프로젝트·version을 기존 친구 저장과 동일하게 검증한다. 다른 일반 정보는 덮어쓰지 않고 변경 후 전체 친구 응답을 반환한다. 오래된 version은 409, 권한 없음/연결 회수는 기존 403/404 정책이다. 상태 필드 DB 구조는 기존 migration 000009를 사용하므로 상태 API만을 위한 신규 DB 변경은 없다.

앱의 친구 목록은 개인돌봄/공동돌봄 텍스트 배지를 표시한다. 공동돌봄 TNR 진행 중 필터가 실제 단계와 날짜를 사용하며 개인 SQLite에 저장하지 않는다. 상세 카드와 정보 수정 화면은 개인돌봄의 동일한 단계/상태 선택 UI와 날짜 선택기를 재사용한다. 상세 카드는 전용 API로 즉시 저장하고, 전체 수정 폼에서는 저장하기 전까지 초안만 변경한다. 날짜 선택 취소 시 요청을 보내지 않는다. 서버 충돌·권한 회수 시 기존 폼에서 재저장하지 않고 새 정보를 조회한다.

### 닉네임

`display_name` 본문과 UNIQUE `nickname_tag`를 분리하고 표시용 `nickname`을 응답한다. 표시 이름은 중복 가능하며 번호는 이름 변경 시에도 고정된다. migration 000014가 기존 계정의 빠진 번호·이름을 보완한다. 상세 계약과 배포 명령은 `docs/NICKNAMES.md`를 따른다. 이 내용이 이전 display_name에 번호를 합쳐 저장하는 방식을 대체한다.
